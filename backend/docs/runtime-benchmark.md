## 范围

这是实际 C Runtime 的调度、角色查找/指令拼接、聚合上下文页读取、Flow 分层启动和事务文件恢复。任务主体使用确定性的本地工作负载，DAG 使用离线 mock LLM；没有远程模型费用，也不包含生产模型推理或网络延迟。这些数字不能作为真实业务 Agent 总吞吐保证。

上下文为测试程序为100个Agent分配的聚合缓冲，由真实 scheduler runner逐页读取；没有把128 MiB文本发送给模型。历史空间为scheduler自身估算，峰值工作集为操作系统读数。当前宿主物理内存约8 GiB、空闲约1.2 GiB，本次采用128 MiB压力案例；**没有宣称测过1 GiB**。程序支持独立调节Context至2048 MiB，可在资源充足的机器运行1024 MiB案例。

## 复现

Windows：`./build.ps1 -Target runtime-bench`；POSIX：`make build/bench-runtime`。

```
# 必须使用独立非Git的临时目录，避免现有工作区快照策略干扰文件回滚。
build/bench-runtime STATE_DIR 10000 128 32
# 参数依次是任务数、聚合上下文MiB、DAG深度（最多64）。
# 资源充足机器的1GiB案例：
build/bench-runtime STATE_DIR 1000 1024 32
```

Windows可执行文件带 `.exe`。脚本 `python tests/test_runtime_benchmark.py` 自动创建/清理临时目录并运行小规模CI回归：100 Agent、1000任务、4MiB、深度8。测试断言工作全部完成、失败后恢复、回滚内容一致、延迟分位数有序；不设置不稳定的性能阈值。

原始数据记录编译器/优化参数和OS；需要不同平台、优化等级或生产负载结果时，应在相同版本上重新测量并保留JSON。
