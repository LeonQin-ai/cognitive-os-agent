# 源码阅读提前结束修复

跟踪：[#96](https://github.com/LeonQin-ai/cognitive-os-agent/issues/96)、
[#97](https://github.com/LeonQin-ai/cognitive-os-agent/issues/97)。

用户提供的实际记录中，仅枚举目录、读取 README 和几个核心文件后，重复读取保护
结束了任务。兜底答案明确列出未读源码，界面却显示执行完成。

## 修改

- 整轮重复读取先给予一次恢复机会，提示选择未读文件或继续分页。新动作重置连续
  重复计数；持续重复仍有界停止，但返回未完成状态。
- 因空转或轮次预算结束而生成的兜底总结不再作为完成证据，保留部分结果并标明
  任务未完成，避免写入“已完成”共享记忆。
- 对明确要求完整源码阅读的请求，记录已打开但尚未连续读到 EOF 的文件和下一
  字节偏移；阻止带未读清单的答案提前完成，并提示继续阅读。
- 单页从 7000 字节改为 4000 字节，返回明确的 `next_offset_bytes`，UTF-8 字符
  不在页边界被拆坏。分页信息使用原始字节偏移。
- 上下文按单个工具观察记录截断，不再对一整批文件结果只保留头尾。总上下文
  预算仍受限制，旧观察折叠后允许重新读取。

分页追踪用于已打开的文件，不是整个仓库的自动覆盖率证明。规划器仍负责枚举用户
要求范围内的相关文件；本次提示明确要求区分目录清单与源码内容，并继续未读文件。

## 验证

从 `backend` 目录运行：

```powershell
./build.ps1 -Target test
./build/cognitive-os-agent-test.exe --agent-loop
./build/cognitive-os-agent-test.exe
./build.ps1 -Target cli
python tests/test_source_read_e2e.py
```

- Windows 完整单元套件：2783 通过，0 失败。
- 推理循环专项：148 通过，0 失败。
- 实际 HTTP、调度器、OpenAI 适配器和文件工具端到端：4 个场景通过，覆盖重复
  目录恢复、部分答案后补读、批量中间源码保留，以及持续重复的失败状态。
- 工具测试将 9000 字节中文源码逐页拼接，确认 UTF-8 合法且所有原始字节完整。
- 端到端使用本地响应服务，无真实模型或付费 API 请求。未测量特定模型对大型
  仓库的阅读覆盖率。
