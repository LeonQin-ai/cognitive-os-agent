# 源码读取失败分析与修复

用户提供的记录显示 105 次动作、31 次失败。多数失败项没有展开错误正文，
不能把每一次失败都归为同一原因。可以直接确认：

1. 相对 `src/memory/service.c` 被解析到 `./src/`，实际文件在 `backend/src/`。
   换成绝对路径立即成功。glob 原先只输出搜索根内部路径，容易丢失 backend 根。
2. 请求 `max_bytes:8000` 被 4000 上限拒绝；多个文件反复出现同类失败。
   模型目录中的 schema 被截断为 200 字节，且 schema 根本没有页大小 min/max。
3. `src/memory/record.h`、`src/memory/episode.h` 属于错误目录推测，实际头文件在 include/。
4. 端到端复现另发现：随机临时目录的真实路径被熵检测误脱敏，导致发现结果无法读取。

## 修复

- #112：glob、list_dir 和 file_read 的目录结果使用绝对 UTF-8 路径，原样传回可读取。
  缺失文件错误区分不存在和不可读取，附工作区与重新 glob/list_dir 的指引，不自动猜测别的文件。
- #114：只有文件系统确认存在的绝对路径排除熵启发式误报；密码/token 等确定性规则继续执行。
  随后用户明确要求仅脱敏 SSH 密码，#115 将运行时所有通用检测移出自动过滤链路；
  #114 的通用检测修复只保留在显式诊断工具中，普通路径、源码和其他凭据不再自动脱敏。
- #113：完整工具 schema 暴露 minimum/maximum/default；描述明确 4–4000 字节页和实际续读偏移。
  大于 4000 的有效整数请求安全降为 4000，并在结果标明实际页限制；跟随 next_offset_bytes
  读取，避免失败或按请求的 8000 跳过内容。负数/小数偏移不再静默当作 0。

## 验证

原生用例覆盖发现后原样读取、嵌套搜索根、目录读取、缺失路径指引、真实高熵文件路径、
路径中真实 token 仍脱敏、8000 请求降页及无效分页参数。

真实 HTTP/调度器/模型协议/工具链用例：错误相对路径 → 明确错误 → 搜索 backend →
原样读取绝对路径 → 有真实源码证据的答案；8000 请求 → 实际 4000 页 → offset=4000 → EOF。
`python tests/test_source_read_e2e.py` 共 7 场景通过，不调用付费模型。
`cognitive-os-agent-test --file-tools` 146 项通过、0 失败。

用户的最终脱敏范围及相关验证见 [ssh-only-redaction.md](ssh-only-redaction.md)。

这些改动修复工具输出和契约，不保证模型永远不尝试错误路径；实际错误会保留并提供恢复信息。
